# juvelook 认证查询系统（一期）

面向微信公众号的认证查询 H5 + 医生扫码核销端 + 运营后台。合同范围见《juvelook 认证查询系统（一期）软件技术开发合同》。

## 本地运行

需要 Node.js ≥ 22.13（使用内置 `node:sqlite`）。

```bash
npm run install:all
npm run build                 # 构建 H5 与后台
npm run seed                  # 写入虚拟数据并创建后台账号 admin（随机密码，打印在终端）
npm start                     # http://localhost:3100
```

开发时前后端分开跑：`npm --prefix server run dev` + `npm --prefix web run dev`（http://localhost:5173 ，后台为 /admin.html）。

- **后台账号**：`npm run seed` 时创建 `admin`，可用 `ADMIN_PASSWORD=xxx npm run seed` 指定密码；之后用 `npm --prefix server run admin -- <用户名> [密码]` 新建或重置账号。
- **医生端演示登录**：认证编号 `JVL-D0001`，手机号 `13900000001`（第 n 位医生为 `JVL-D000n` / `1390000000n`）。
- **模拟验真规则**（`VERIFY_MODE=mock`，默认）：12–24 位数字；末位奇数 = JUVELOOK，偶数 = JUVELOOK Volume；以 `0000` 结尾 = 无法识别；以 `9999` 结尾 = 已过期；以 `7` 开头 = 窜货标记。
  例：`86173880123456789013`（JUVELOOK）、`86173880123456789012`（Volume）。

```bash
npm test                      # 后端接口测试
```

## 生产部署

```bash
npm run install:all && npm run build
PORT=3100 DB_FILE=/var/lib/juvelook/juvelook.db SECURE_COOKIE=1 \
VERIFY_MODE=huaxi VERIFY_URL=https://<正式验真地址> \
WECHAT_APPID=wx... WECHAT_SECRET=... npm start
```

同一进程提供 `/api`、H5 与后台静态文件。Nginx 负责 HTTPS 并反代到 3100。公众号后台需把部署域名配置为「JS 接口安全域名」。

| 环境变量 | 默认值 | 说明 |
|---|---|---|
| `PORT` | `3100` | 监听端口 |
| `DB_FILE` | `data/juvelook.db` | SQLite 数据库文件（定期备份此文件） |
| `SECURE_COOKIE` | 关 | HTTPS 部署时设为 `1` |
| `VERIFY_MODE` | `mock` | `huaxi` 接入华熙一物一码验真接口 |
| `VERIFY_URL` | 华熙测试地址 | 验真接口地址 |
| `VERIFY_ALLOW_EXPIRED` | 关 | 联调用：允许核销过期产品（测试码已过期时） |
| `VERIFY_FALLBACK_KIND` | 无 | 联调用：产品名无法判定品类时按 `blue` / `black` 处理 |
| `WECHAT_APPID` / `WECHAT_SECRET` | 无 | 公众号凭证；配置后医生端启用微信扫一扫 |
| `ADMIN_USERNAME` / `ADMIN_PASSWORD` | `admin` / 随机 | 仅 `npm run seed` 创建初始账号时使用 |

## 小程序扫码数据导入

后台「数据导入 → 小程序扫码数据」直接上传小程序后台导出的「扫码验真记录」表格（列：用户ID、用户姓名、手机号、用户身份、验证结果、产品名称、产品标识、批次号、产品名称（显示）、使用期限、验证时间等），无需改格式。

- 只计入「用户身份」含「医生」且「验证结果」为「正常」的行；消费者验真、异常结果跳过。
- **按「产品标识」去重**：产品标识是 GS1 UDI（含 GTIN、有效期、批号、序列号），每支产品唯一。同一支多次扫码、同一文件重复导入都只算一次。
- **按手机号对应医生**；找不到医生、手机号对应多位医生、机构未授权该产品、无法判断品类的行列为「需处理」，不计入。处理后重新导入同一文件即可补上。
- 品类按「产品名称（显示）/ 产品名称」判断：小程序中为「JUVELOOK蓝瓶」→ JUVELOOK，「JUVELOOK黑瓶」→ JUVELOOK Volume（另兼容名称含 Volume 的情况）。客户确认：医生扫码一次即计一支。
- 表格「用户姓名」与系统中该手机号医生的姓名不一致时，预览中标注提示核对（仍计入），防止因手机号录错把支数算到别人名下。
- 每次导入记一个批次（`scans.batch_id`、`source = import`），扫码时间取表格中的「验证时间」，操作日志记录汇总。

## 关键规则

- **一码一核销**：防伪码在数据库中唯一，重复扫提示「已于某时由您 / 其他医生核销」；并发扫同一码由唯一约束兜底。
- **品类判定**：按验真接口返回的产品名（含 Volume → JUVELOOK Volume，含 JUVELOOK → JUVELOOK），见 `verify.js` 的 `classifyProduct`。客户若有更可靠的字段，改这一处。
- **核销拦截**：验真未通过、品类无法识别、产品过期、医生所在机构未授权该品类，均不计数。验真平台标记窜货（`position = 1`）时照常核销但标记预警，后台可筛选。
- **支数**：医生支数 = 初始录入 + 扫码累加。后台可人工修改（记入操作日志，含修改前后值）；Excel 导入只对新增医生写初始支数，不覆盖已有医生。
- **撤销认证**：医生 / 机构设为「已撤销」后，前台立即不可查，医生端会话失效。有核销记录的医生、名下有医生的机构不能删除，只能撤销。
- **安全**：密码 scrypt 哈希；会话 token 仅存哈希，HttpOnly + SameSite Cookie；登录 15 分钟内失败 5 次锁定；API 按 IP 限流；对外 ID 为随机串；前台查询必须带条件且最多返回 50 条。
